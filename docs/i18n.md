# 中英文多语言支持（next-intl）

> 日期：2026-10-24
> 方案：**next-intl v4 + Cookie 切换（URL 不变）**

## 1. 方案选型

| 决策点 | 选择 | 理由 |
|---|---|---|
| i18n 库 | [next-intl](https://next-intl.dev)（v4.14.9） | App Router/PPR 集成成熟，自动处理 SSR 水合与语言协商 |
| URL 策略 | Cookie 切换，路由不变（无 `/en` `/zh` 前缀） | 零路由重构：`proxy.ts` 保护路径、Stripe redirect、`/api/*` 全部不受影响 |
| Cookie | `NEXT_LOCALE`（next-intl 约定名），max-age 1 年，`path=/; samesite=lax` | |

**已知代价**：读取 cookie 使所有使用翻译的页面从静态预渲染（◐ PPR）变为按需动态渲染（ƒ）。对 starter 项目可接受；若未来需要静态多语言 + SEO，应迁移到 `[locale]` 路径段方案。

## 2. 架构

```
i18n/
├── config.ts      # 共享常量：locales、Locale 类型、defaultLocale、LOCALE_COOKIE、localeLabels
│                  # ⚠️ 被客户端组件导入，禁止引入 next/headers 等服务端 API
└── request.ts     # next-intl 请求配置：读 NEXT_LOCALE cookie → 选择 messages/{locale}.json
messages/
├── en.json        # 英文字典（默认语言）
└── zh.json        # 中文字典
components/
└── locale-switcher.tsx  # Header 上的 Globe 下拉切换器（写 cookie + router.refresh()）
```

- `next.config.ts`：`createNextIntlPlugin('./i18n/request.ts')` 包装；同时新增 `turbopack.root = __dirname`（本机 home 目录存在 yarn.lock，会导致 root 推断错误）
- `app/layout.tsx`：
  - `const locale = await getLocale()` → `<html lang={locale}>`
  - `<NextIntlClientProvider>`（无 props，自动从服务端继承 locale + messages）包裹全站，客户端组件可直接 `useTranslations`
  - `metadata` 改为 `generateMetadata()`，标题/描述走 `Metadata` 命名空间翻译

## 3. 翻译接入模式

| 场景 | 用法 | 示例文件 |
|---|---|---|
| 客户端组件 | `const t = useTranslations('Ns')` | header.tsx、login.tsx、dashboard/* |
| 服务端组件（同步） | `useTranslations('Ns')`（next-intl 在 RSC 中可用） | footer.tsx、page.tsx（落地页）、activity/loading.tsx |
| 服务端组件（async） | `await getTranslations('Ns')`（from `next-intl/server`） | pricing/page.tsx、activity/page.tsx |
| 富文本（JSX 内嵌） | `t.rich('key', { gradient: (c) => <span …>{c}</span> })` | hero/定价标题的渐变词、footer builtWith |
| ICU 插值/复数 | `t('minutesAgo', { count })` → `{count, plural, one {# minute ago} other {…}}` | Activity 相对时间 |
| 数组数据 | `t.raw('features.items') as {...}[]`，图标/组件仍留在代码里按 index 配对 | 落地页 features/stats/testimonials/faq、pricing 套餐特性列表 |
| 动态 key + 兜底 | `t.has(\`actions.${action}\`) ? t(key) : t('actions.UNKNOWN')` | activity/page.tsx formatAction |

## 4. 字典命名空间

`Metadata` / `Header` / `Footer` / `Home`（hero、logos、features、stats、testimonials、faq、cta）/ `Pricing` / `Login` / `DashboardNav` / `Team` / `General` / `Security` / `Activity`（含 `actions.*`，key 与 `lib/db/schema.ts` 的 `ActivityType` 枚举值一一对应）/ `NotFound`

**ICU 注意事项**：消息中的英文撇号需写成 `''`（如 `Don''t`），否则会被 ICU 当作转义符。

## 5. 语言切换器

`components/locale-switcher.tsx`：Globe 图标下拉（English / 中文，当前项带 Check）。切换逻辑：

```ts
document.cookie = `NEXT_LOCALE=${next}; path=/; max-age=31536000; samesite=lax`;
router.refresh(); // 重新拉取服务端组件，全站文案即时切换，URL 不变
```

位置：Header 右侧，ThemeToggle 左边（桌面与移动菜单共用同一 Header 实例）。

## 6. 覆盖范围与边界

**已翻译**：落地页全部分区、Header/Footer、Pricing（含 Stripe 价格单位 month/year → 月/年）、登录/注册、Dashboard 导航、Team/General/Security/Activity 页面、404、根 metadata、`<html lang>`。

**未翻译（明确边界）**：
- **Server Actions 返回的 error/success 消息**（`lib/payments/actions.ts`、`app/(login)/actions.ts` 中的英文字符串）——需要在 action 内用 `getTranslations` 才能本地化，属后续增强
- 品牌词（ACME、Next.js、Stripe 等）、Terminal 组件中的命令文本、Stripe 产品名（Base/Plus，来自 Stripe 后台）
- 测试用户可见的数据库内容（用户名、团队名）

## 7. 新增语言步骤

1. 复制 `messages/en.json` → `messages/{locale}.json` 并翻译
2. 在 `i18n/config.ts` 的 `locales` 数组和 `localeLabels` 中登记
3. 完成（request.ts 动态 import、切换器自动渲染新选项）
